# LLess implementation contract

Python FastAPI backend; vanilla accessible HTML/CSS/JS frontend served at /. Python modules in lifeev. Use plain JSON dictionaries across module boundaries, Pydantic only at HTTP boundary if needed. No recommendations or sorting options by value.

Decision document: {title, options:[{id,label,status_quo:bool,outcomes:[{label,probability,probability_low,probability_high,values:{money:float,time:float},black_swan:bool}],costs:{money:float,time:float}}], weights:{money:1,time:0}, weight_version:string, bankroll:{money:10000,time:100}, correlations:[{node_id,rho,exposure}], horizon:string, reversibility:string, thresholds:{money:float}, skipped:[field names]}. Missing fields allowed for drafts; invalid numerical inputs rejected. Outcome values are net benefits BEFORE option costs, same dimensions/units as costs. Weighted utility is distinct from monetary returns.

Storage envelope: {id,version,parent_id,parent_version,created_at,document,frozen_parent,archived_at}. Node id stable across immutable revisions; parent version frozen at creation. Storage Store(path,key) methods create(document,parent_id=None)->envelope, revise(id,document)->envelope, get(id,version=None)->envelope, list_nodes(include_archived=False)->list, save_session(dict)->dict, get_session(id)->dict, list_sessions()->list, add_memory(dict)->dict, list_memory()->list, save_profile(dict)->dict, list_profiles()->list, snapshot(reason)->str, archive(id)->dict, restore(id)->dict, purge(id)->None, audit()->list. Encryption key Fernet bytes. raise ValueError/KeyError for errors.

Skeleton lifeev/skeleton.py: REQUIRED list fields; validate(document)->list[str] errors; gaps(document)->list[dict {field,question,impact}]; assess(document)->dict confidence/completeness/skipped/gaps; accept_override(document,field,accepted)->dict. Explicit skips resolve gaps but remain uncertain.

Stats lifeev/stats.py: analyze(document,approximation=False)->dict {options:[{id,label,...metrics}], confidence, assumptions, method}; chain_probabilities(probabilities,depth_cap=12)->float. No recommendations; return null with reasons when metric unsupported. Metrics keys documented by implementer.

Controls lifeev/controls.py: route(document,force_tier=None,confidence=1)->dict {tier,score,reasons}; VersionCache.get(document,upstream,tier), .put(document,upstream,tier,value); Retriever.upsert(id,text,confirmed=True), .search(query,pins=[],top_k=5)->list. Offline hashed vector and lexical pair rerank explicitly labeled fallback, optional real embedding provider separate if feasible.

Agent lifeev/controller.py: Controller(store).start(document,parent_id=None)->session; .answer(session_id,field,value=None,skip=False)->session; .resume(session_id)->session; .finalize(session_id)->node. Session {id,document,parent_id,round,round_cap:3,questions,history,status}; each round max 3 prioritized questions, rounds count completed batches, persist every answer. No silent overrides; after round cap unresolved fields explicitly marked skipped with provenance. Memory helper propose_memory(store,key,value,confirmed=False) requires conflict review before confirmation.

Monte Carlo lifeev/simulation.py: simulate(documents:list, samples=10000,seed=42, linked=False)->dict; 1 or 2 directly linked nodes only, reject >2 nodes and branching count >=3; explicit dependence assumptions. No recommendation.

API root agent integrates modules. Endpoints GET /api/nodes, POST /api/nodes {document,parent_id}, GET /api/nodes/{id}?version=, POST /api/nodes/{id}/versions {document}, POST /api/analyze {document}, POST /api/sessions {document,parent_id}, GET /api/sessions, GET /api/sessions/{id}, POST /api/sessions/{id}/answers {field,value,skip}, POST /api/sessions/{id}/finalize; POST /api/nodes/{id}/archive, /restore; GET/POST /api/profiles; GET /api/memory; POST /api/memory; GET /api/audit; POST /api/snapshots; POST /api/simulate {node_ids,samples,seed}; GET /api/example.

Frontend: / is a single text box (web/index.html + web/text.js) whose results follow typing via POST /api/quick, with Save as the only write. The monochrome black/white workspace lives at /workspace.html (see DESIGN.md): black sidebar with server status and decision tree, draft summary strip, main stats table + SVG intervals, right record inspector and question panel, status bar from /api/health and /api/audit, tabs for dashboard/inputs/statistics/audit; the dashboard is the default view (one text box -> POST /api/quick {text} -> per-option result cards; text without numbers falls back to a prefilled scenario grid -> POST /api/quick {document}; unsaved until Save). /api/quick is parse + exact statistics only: no model, session, retrieval, tier routing, cache or write. Lines "If I <a> and <who> <b>: <mine>, <theirs>" form a two-player simultaneous game (lifeev/game.py describe): best responses, pure Nash equilibria, strict dominance, worst case, Pareto set, constant-sum flag, 2x2 mixed equilibrium, and expected payoffs under user-stated chances. Descriptive only; no recommended strategy field. Monte Carlo samples render in a dependency-free WebGL field with a table fallback. GET /api/health also reports model_provider configured/not configured. No rankings, advice or synthetic live results. Load example only on user action. JSON editor acceptable for advanced inputs but guided creation form needed.
